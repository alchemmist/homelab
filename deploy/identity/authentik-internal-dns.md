# Authentik internal HTTPS DNS dependency

`auth.socrat.alchemmist.xyz` must resolve **inside Kubernetes** to the existing
private HOME HA HTTPS VIP `192.168.0.250`, not to independently selected public ingress
IPs. Original URL, issuer, Host, SNI, TLS certificate verification and machine
credential permissions stay unchanged. No plaintext transport or new roles.

Desired owned key is generated by `scripts/observer-internal-dns.py`:
`kube-system/coredns-custom.data[authentik-internal.server]`. It verifies the existing Traefik Service UID/IP and pins
the private HA VIP in a fresh plan, preserves all other ConfigMap keys, and
requires public ACME self-check resolver arguments already installed. Exact host
A resolution is internal; subdomain/TXT fallthrough keeps other DNS semantics.
Public authority records, global/Mac resolvers and upstream nameservers are NOT
modified. No node, workload, K3s or CoreDNS restart is required: normal ConfigMap
projection/CoreDNS reload handles propagation.

## Reviewed execution

On approved internal controller, run the script without `--apply` for read-only
preflight and fresh approval hash. An explicitly approved apply needs that exact
hash and a **new** private `--state` directory. Script must be root-owned/private.
Preimage UID/resourceVersion/data are JSON-patch CAS tests; only the one absent
key is added. An existing identical key is accepted without another patch; a
changed/colliding key stops. A prior accepted private `--replace-owned-state`
receipt permits replacing ONLY that exact previously owned value with a fresh
approval/preimage, never adopting a foreign key. Do not blindly overwrite a changed
Service/IP/key.

The approved2026-11-08 state and preimages are private on socrat-0 at
`/var/lib/homelab-observer-rollout/observer-internal-dns-vip-20261108/`.
Initial service-IP attempt is retained separately in
`observer-internal-dns-20261108/` and did NOT pass worker acceptance. The restricted
worker network namespace rejects ServiceIP443 traffic, while private VIP443 passes
verified TLS. VIP API returns HTTP200 with the same scoped machine token. Existing
NetworkPolicy/RBAC were NOT expanded to expose backend high ports.
`receipt.json` exact readback is NOT functional acceptance; verify both CoreDNS
replicas and cluster DNS VIP return the private HA address, same machine reader's HTTPS snapshot
works, three successive natural CronJobs succeed, and freshness alert clears.
Record runtime acceptance separately. Native credential values must never appear
in logs/Git/argv/environment or issue comments.

## Uncertain-stop / rollback

If `uncertain.json` exists, inspect preimage/plan/write-response and live UID/data;
do not rerun apply. A fresh readback can finalize the original successful write
without replay if all planned invariants match. If failure requires rollback,
obtain current exact preimage, confirm this key still equals its approved value,
then CAS-remove **only** `/data/authentik-internal.server`. Never restore the whole
old ConfigMap, delete its Rancher key, flush caches, or restart the cluster.
Rollback returns the known public-entry failure dependency and is not a repair.

## Why

During partial public VPS reachability failure, authoritative zone refresh on VPS
sees loopback443 healthy and advertises VPS, while HOME publishes HOME. The two
CoreDNS pods inherit different upstream views and return different addresses.
Observer task intermittently reaches blocked VPS443 and stops before a complete
membership snapshot. Scope this internal dependency rather than weakening revoke
freshness, rotating valid tokens, or globally rewriting public DNS/failover.
