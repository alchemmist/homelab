# Qwen non-thinking sampling and incremental writing

The Open WebUI workspace model `qwen3.8-27b` uses the upstream Qwen3.8-27B non-thinking recommendations:

| Parameter | Value |
| --- | --- |
| temperature | 0.7 |
| top_p | 0.8 |
| top_k | 20 |
| min_p | 0.0 |
| presence_penalty | 1.5 |
| repetition_penalty | 1.0 |

Apply the model defaults and terminal instructions without restarting inference:

```sh
cd ansible
ansible-playbook playbooks/open-webui-sampling.yml playbooks/open-terminal-instructions.yml
```

The standard WebUI deployment also applies the sampling defaults. The helper skips an absent workspace model and otherwise merges parameters through the administrative model API. System instructions, output allowance, metadata, ownership and access grants are preserved. Conflicting sampler keys are removed from `custom_params`, which otherwise override ordinary parameters. Explicit per-chat/request parameters still take precedence over model defaults.

Open WebUI forwards these parameters to LiteLLM. Its OpenAI provider forwards the additional vLLM parameters through `extra_body`; the OpenAI SDK flattens them into the backend JSON. The gateway records only a numeric sampler allowlist and request ID before forwarding, without recording chat text or credentials. This allows verifying that settings reach the serving boundary.

The managed terminal instructions recommend roughly 8,000 characters or 150 lines per file-writing call, then appending sections or using targeted edits. They also require checking the destination after malformed JSON instead of repeating a huge call. These are model instructions, not hard API limits. A final deliverable can still be one large HTML file; repetitive data can be generated by a short script.

These measures reduce the risk of repetitive generation and truncated tool arguments. They do not implement a streaming repetition detector or guarantee that all long tasks will complete. Changing thinking mode requires revisiting the sampling profile.

Reference: https://huggingface.co/Qwen/Qwen3.8-27B#best-practices
