# Browser test cleanup

Open Terminal's execution wait timeout controls how long the API waits for output; it does not terminate the command. Completing a model response also does not stop its terminal processes. A Playwright exception before `browser.close()` can therefore leave a continuously rendering Chromium alive.

Managed instructions require browser tests to run through `homelab-browser-test --timeout 180 -- node test.js` (or a Python script), close the browser in `finally`, and check the process exit code. The Linux wrapper becomes a child subreaper, tracks its descendants including separate sessions and double forks, and terminates them on command success, failure, timeout or interruption. Timeout returns 124; command failures retain their exit status. It uses PID start times and pidfds to avoid signaling a reused PID. Test artifacts are retained. Intentionally persistent servers must run outside this test wrapper.

An independent sidecar shares the terminal pod's process namespace and bounds directly launched headless Playwright Chromium browsers to 900 seconds. It identifies browser roots by executable name, headless mode, debugging pipe and a temporary `/tmp/playwright_*` profile. It tracks observed descendants, sends TERM at the age limit, then KILL after a grace period. The limit is total browser age, not idle time, and can interrupt a long active test. It is configurable through `browserCleanup` chart values. The sidecar does not kill Node/Python parents or arbitrary background servers, and cannot discover already reparented descendants it never observed. The test wrapper handles that stronger cleanup scope.

The chart deploys both scripts through a ConfigMap. The sidecar runs as the same unprivileged UID as Open Terminal with all capabilities dropped. It does not receive the terminal API key or mount the workspace. Disabling `browserCleanup.enabled` removes the sidecar and wrapper. Applying this change restarts Open Terminal; persistent workspace files remain on its volume.

Chromium system libraries are declared in `systemPackages` and installed through the image's native `OPEN_TERMINAL_PACKAGES` startup setting. Previously manually installed libraries disappeared on container replacement even though the browser executable survived in the workspace. Startup now requires access to Debian package repositories to restore these dependencies.

Deploy with `ansible-playbook playbooks/open-terminal-browser-cleanup.yml` from `ansible/`. Existing release values are preserved. The standard terminal playbook also deploys cleanup from the chart.

Run watchdog unit tests with `python3 -m unittest discover -s tests -p test_browser_watchdog.py -q`. Run `test_browser_test_runner.py` on Linux: its real process tests intentionally skip on other operating systems. These cover successful and failed commands leaving detached children, hard timeout, signal interruption, double-forked descendants and survival of an unrelated process.

Validation on 2026-10-19: 14 watchdog unit tests and five Linux process tests passed. `scripts/check-terminal-browser-cleanup.py` ran against real Chromium in the deployed terminal: an intentional exception without browser cleanup left it running, the wrapper expired at eight seconds with exit 124 and removed captured descendants; a separate browser was expired by the watchdog with a one-second test lifetime while an unrelated marker process survived. Production lifetime remained 900 seconds. The probe accepts explicit browser, Playwright module and watchdog module paths and cleans its own fixtures.
