# redis-common: platform and LiteLLM operations

One client endpoint: `redis-common-haproxy.redis.svc.cluster.local:6379`, TLS only. Three Redis instances each colocate a Sentinel; the third data copy buys a third voter without another controller and keeps `min-replicas-to-write 1` viable after promotion. Sentinel quorum 2; two HAProxy pods pass through client TLS only to a Redis primary identified by at least two voters. Neither replication nor AOF everysec guarantees zero data loss. No independent backup/PITR. 192 MiB maxmemory per instance, noeviction: writes can fail at the cap. Never place authoritative balances or a second untrusted tenant here on the strength of ACLs alone.

## First rollout

1. Review/publish the Git sources. `storage-tiers` owns the local-path provisioner map; confirm it reloaded `redis-local-retain` and that 0/1/5 have disk and memory headroom before binding. These are retained, node-local PVCs; 2 GiB is nominal capacity, not a filesystem quota. Do not delete PVCs for rollback.
2. The root registers the **manual-sync** `redis-common` Application. Sync its StorageClass, namespace/PKI prerequisites first (or initially sync the App: pods wait for Secrets). Wait for the namespaced CA and leaf Certificate. No public issuer or exported private CA key.
3. From the approved Socrat context run `bash deploy/platform/redis-common/bootstrap.sh --create-missing`. It creates distinct random control/Sentinel passwords, a disabled workload ACL, and public CA trust for the gateway. Existing secrets are never rotated. Complete the targeted application sync. Check 3 distinct nodes, 3 bound retained claims, 3 Ready Redis/Sentinel pods and 2 Ready gateways. Argo Healthy alone is not a write check.
4. Before enabling LiteLLM, admit only a dedicated test pod to the gateway port and use a scoped test ACL. Test wrong CA, wrong hostname, denied command, write/read, automatic promotion and fresh connections; remove temporary access. Confirm actual alert delivery for a missing writer, memory pressure, replica loss and local disk; test budget and invalidation separately. The [Docker receipt](../experiments/redis-common/README.md) does not certify Kubernetes failure behavior.
5. Separate consumer change: enable named ACL with measured command/key permissions; distribute **only** its credential and public CA to `llm`, allow exact LiteLLM pod labels to gateway TCP/6379. Never distribute `redis-common-control`. Set external `general_settings.coordination_redis`, keep bundled Redis and response caching off. Canary first, keep production workers/replicas unchanged. Revert the consumer change if needed: local enforcement only. No blind prune or reinitialization.

## Maintenance

CA/leaf rotation requires explicit coordination: establish overlapping public trust in gateway and all clients, roll/reload, then rotate leaf certificates on one Redis/Sentinel pair at a time and prove reconnect with strict validation. Update mounted certs alone does not reload every process. Retire old trust last. Monitor expiry. Chart init resolves the three per-ordinal announce Service IPs; if Services are ever recreated, reinitialize gateway pods one at a time. No claim of a hard spend ceiling: the pinned LiteLLM image admitted excess RPM during a tested outage.
