# Единые логи: руководство оператора

## Доступ и границы

В Grafana откройте **Dashboards → Socrat / Unified logs** (`/d/socrat-unified-logs`). Используется штатный Loki datasource с UID `loki`, не Prometheus/Thanos. На момент read-only проверки datasource расположен в `cattle-monitoring-system`, обращается к Loki по HTTPS с проверкой CA и клиентским TLS-сертификатом; ключи остаются в существующем Secret. Дашборд не содержит паролей и не меняет авторизацию. Доступ к логам определяется правами Grafana, а не переменными дашборда: фильтр namespace не является границей безопасности.

ConfigMap дашборда создаёт chart `monitoring-k3s`, label `grafana_dashboard=1`. Существующий sidecar читает все namespace и использует `grafana_folder`. Не редактируйте provisioned JSON через UI: изменения должны пройти Git-review. Остальные datasource, метрики, Thanos и базы приложений этим изменением не затрагиваются.

## Поиск

1. Выберите период справа сверху (по умолчанию час), затем Service, Namespace, Node и Severity. Множественный выбор поддерживается. All для namespace/node/severity включает отсутствующие метки, поэтому host-логи без namespace видны без дополнительной настройки. Service All требует непустой `service_name` (`.+`), как требует безопасный селектор Loki; записи без service_name надо искать отдельно в Explore по другому непустому label и исправлять их нормализацию.
2. Графики показывают число записей по сервису за динамический интервал и число error/fatal. Панель ошибок также учитывает выбранный Severity: при выборе только info она закономерно пуста.
3. Панель логов ограничена 1000 строками; уменьшите интервал или перейдите по **Explore — same filters and time**. Ссылка переносит выражение LogQL и абсолютные границы текущего периода. В Explore можно добавить поиск по строке и просматривать детали записи. Не помещайте пользовательские тексты, trace ID, pod UID или имена файлов в индексные labels.
4. Severity: trace, debug, info, warn, error, fatal, unknown. unknown означает неклассифицированный уровень, не info. Старые записи без severity видны при All, но не при выборе unknown. Поля pod/container/systemd unit ищите в деталях (structured metadata), а не в списке индексных переменных.

**No data не означает исправность или нулевое число ошибок.** Сначала сбросьте фильтры и увеличьте период. Затем проверьте доступность datasource, доставку collector → Loki и окно retention. Список сервисов строится по уже поступившим логам: отсутствующий в нём сервис не доказательство отсутствия сервиса. Полноту покрытия сравнивайте с инвентарём Kubernetes и host-служб. Дашборд не подменяет независимую проверку доставки.

## Retention и дисковая ёмкость

Дашборд читает данные и не управляет удалением. Изменения retention должны проходить через управляемую конфигурацию Loki и review: базовый срок плюс исключения по `service_name`/`severity`, приоритеты правил, минимальное поддерживаемое окно. Уменьшение срока — потенциально необратимое удаление, увеличение не возвращает удалённые записи. Срок считается не жёсткой квотой диска: compaction/delete delay и текущая скорость поступления дают запас сверх срока.

Перед rollout зафиксируйте только агрегаты: размер filesystem и свободное место, размер Loki chunks/index/WAL, байт/сутки за репрезентативный период, скорость роста, задержку compactor и запас до заполнения. Оценка: дневной рост × срок хранения + WAL/index/compaction + резерв. Не заявляйте измеренный предел без реальных измерений. Точные бюджет и пороги берите из согласованной конфигурации хранения; при недостатке места сначала ограничьте поток/срок согласованно, не удаляйте каталоги вручную. Не трогайте каталоги Prometheus, Thanos или базы приложений.

## Безопасное внедрение и проверка

Текущая фаза — только локальная реализация: без apply, sync и push. Перед одобренным rollout: запустить offline-тесты и `helm template`, проверить ConfigMap, затем применить только согласованный GitOps change. После rollout проверить загрузку dashboard, существующий UID `loki`, фильтры на реальном сервисе/узле, каждый уровень и legacy missing labels, переход Explore (фильтры + время), пустой период и недоступный datasource. Проверять доставку по безопасному синтетическому маркеру; не сохранять тела рабочих логов, токены, сертификаты или скриншоты чувствительных записей в evidence.

Откат UI: вернуть commit дашборда/ConfigMap через штатный GitOps. Это не откатывает уже выполненное удаление retention. Не восстанавливайте Loki посредством удаления PVC и не меняйте существующие datasource Secret при откате UI.
