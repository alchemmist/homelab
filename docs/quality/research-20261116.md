  [required checks](https://quality-graph.xyz/required-checks/): secretless execution,

  future checkpoint semantics. Neither deployment nor release is added here.
- [Provider authoring](https://quality-graph.xyz/provider-authoring/),
  [integration testing](https://quality-graph.xyz/testing/): deterministic providers,
  production transports, stateful fakes, rerun/attempt and malformed-report tests.
- [GitLab](https://quality-graph.xyz/gitlab/),
  [GitLab laboratory](https://quality-graph.xyz/gitlab-testing/): separate trusted
  publisher and isolated disposable lab. No GitLab instance was started or changed.
- [Adopter discovery](https://quality-graph.xyz/adopter-discovery/) and homepage:
  claimed adoption is not inferred merely from mentioning an Action.

The installed0.1.8schema lacks `operations`, although the site teaches it and
producer-only reports. The latest published release at review was0.2.0; the
annotated release tag resolves to `3b0cf7d8a33215d5a3bb5521b4e0e41c18e8cb7c`.
CLI/provider/runtime were therefore upgraded together first, retaining existing
commands and topology. This bootstrap passed main CI43930408114.

The expansion retains graph-v0 nodes deliberately: replacing existing operations
and governance simultaneously would complicate base-branch admission/parity.
Modern producer data is used for custom lints; JUnit for tests. Profile inheritance
and real prerequisites give independent branches, not a linear lint→all-tests wall.
A dedicated main-only node performs the explicitly online vulnerability audit.

PR interaction remains Quality Graph's own implementation: `/qg status`, `/qg help`,
semantic finding approvals and their inverse `/qg remove-ignore` command. Security,
chart/data and CI integrity nodes disable approval escape hatches. Other quality
findings retain administrator-controlled semantic approvals; file/node blanket
approvals are not enabled. No branch-protection or label API mutation is performed.

## Rule → tool → repository policy

The exact selected278Ruff rule descriptions,31KubeLinter check descriptions and
13enabled YAML rule names are checked in at `quality/rules.json`. The table below
explains the policy families and the additional repository-specific rules.
Tools are version/hash locked, not installed with floating `latest` selectors.

| Rule or family | Tool / source | Scope and decision |
| --- | --- | --- |
| Python syntax, undefined names, invalid imports/control flow | Ruff E9/F | All owned tracked `.py`; known semantic findings ratcheted, not auto-fixed |
| Bug-prone closures, exception handling, mutable defaults, iteration | Ruff B | Same tree, exact context IDs rather than per-file blanket ignores |
| Supported Python idioms and modernization | Ruff UP | Repository interpreter contract3.13; no automatic production-source upgrade |
| Unsafe subprocess/exec/eval, hardcoded credentials, TLS/URL risks | Ruff S | Operational tools still need human intent review; a fixed recovery IP is not itself a bug |
| Comprehension and simplification correctness | Ruff C4/SIM | Bounded selected families rather than enabling every stylistic rule blindly |
| Deterministic style of the newly added CI implementation | Ruff formatter/check | Strict on `scripts/quality` and its tests, no legacy baseline for our new code |
| YAML syntax, duplicate keys, trailing whitespace, basic hygiene | yamllint | Raw non-template YAML; indentation/line length are not mass-imposed on legacy trees |
| Shell quoting, word splitting, test/array/portability bugs | ShellCheck | Owned `.sh`, parse-only; explicit `--norc`, no script invocation |
| Dockerfile AST/build/package/shell practices | Hadolint | Owned Dockerfiles; explicit config; no Docker build or container execution |
| Ansible safety/idempotence/permissions/names/schema | ansible-lint safety | Explicit file inventory, offline; currently diagnostic/advisory because of a reproduced tool crash |
| Action YAML, expressions and job semantics | actionlint | All workflow files; inline ShellCheck integration is separately identified below |
| Dangerous triggers, expression injection, overbroad credentials | zizmor offline | All workflows; exact deliberate compiler publisher finding documented, no global dangerous-trigger ignore |
| Source-tree credential exposure | Gitleaks redacted | All regular tracked files, including vendors, in a private disposable staging tree; no `.venv` or private evidence scan |
| Python dependency vulnerabilities | pip-audit | Installed locked quality environment; main-only online feed; not the entire runtime fleet |
| JavaScript syntax | Node24 `--check` | Owned `.js` only, never execute scripts; not ESLint/type/accessibility certification |
| Helm template/chart conventions | Helm3.19 lint | Every local chart root, no repository/dependency downloads |
| Real consumed Helm values | Local Argo source resolver + Helm template | Release/namespace/ordered value files/registered `$values`/parameters; reject unsupported override fields |
| Kubernetes type/required-field/unknown-field validation | kubeconform strict | Rendered manifests,1.36.0minor baseline, local SHA-inventoried schemas; no network schema fallback |
| Duplicate rendered YAML keys | Strict SafeLoader subclass | Reject before converting YAML to JSON, otherwise duplicate information would be lost |
| Duplicate rendered object identity | Python repository checker | Per rendered target `(apiVersion,kind,namespace,name)` |
| Deprecated APIs, container/security/probe-port/resource/reference practices | KubeLinter31defaults | Complete rendered target at once, preserving service/selector relationships |
| Host IPC/PID/network, privilege escalation, privileged containers | KubeLinter | Existing node/network/bootstrap exceptions remain debt; never auto-remove required privileges |
| Non-root, read-only filesystem, dangerous mounts/capabilities | KubeLinter | Explicit findings, not proof that all kernel/runtime conditions are safe |
| Memory limits and CPU requests | KubeLinter | Do not invent CPU limits or new placement/resource budgets merely to satisfy a linter |
| Image immutability stronger than “not latest” | Python image-digest rule | Init and regular containers must carry a digest, with exact existing exceptions |
| Existing persistent volume data retention | Python pv-retain rule | `Retain` intent; explicitly NOT a backup/DR claim |
| Cluster-admin binding ownership | Python binding rule + ownership contracts | Owner-reviewed exceptions, not automatic RBAC mutation |
| One Argo owner, bootstrap refusal, endpoint/source/inventory coherence | Existing repository checkers | Reuse and retain established scoped contracts, rather than replace them with regexes |
| Vendored dependency/alias drift | Existing vendor checker + schema/tool locks | Reviewed bytes, not independently authenticated upstream provenance |
| All supported Python test styles actually collected | pytest + JUnit | Explicit reviewed modules, both unittest classes and ordinary test functions |
| New tests cannot silently remain unclassified | Python quality contracts | Scheduled/not-yet-scheduled partition exactly equals tracked test inventory |
| Stale reports cannot turn a failed setup green | Runner report removal + QG admission | Delete JUnit output before each run; malformed/missing reports remain failures |
| Tools cannot hide failures behind a quality baseline | Native `failureKind=command` | A crash, timeout, missing binary or malformed parser output is not technical debt |
| No accidental production networking from new test suites | Linux network namespace | Loopback enabled, no external interface/routes; credentials stripped. Not a hostile-code sandbox on a sudo-capable runner |

## Why these choices rather than the alternatives

### Helm and Kubernetes

Sources: [Helm best practices](https://helm.sh/docs/chart_best_practices/),
[chart-testing](https://github.com/helm/chart-testing),
[kubeconform](https://github.com/yannh/kubeconform),
[KubeLinter](https://docs.kubelinter.io/),
[Kubernetes probes](https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/).

- `helm lint` alone does not certify Kubernetes schemas or consumed production
  overrides. Rendering only defaults would miss most deployment composition bugs.
- chart-testing is useful for packaged-chart metadata/version/install workflows.
  This repository also has raw sources, multiple values owners and intentionally
  vendored charts; we use the actual Argo composition rather than pretend a
  changed-chart default install represents the cluster. `ct install`/kind is a
  later disposable integration lane, NOT an operation against the real cluster.
- kubeconform is selected over replacing Kubernetes schemas with hand-written
  Python validation.25strict built-in schemas are vendored from one immutable
  upstream commit, with Apache license retained. Missing CRD schemas and the
  unavailable apiextensions CRD schema are explicit findings, not an unbounded
  `-ignore-missing-schemas` switch. These gaps remain open, scoped debt.
- KubeLinter is selected for standard workload practices rather than duplicating
  its security/probe/reference checks in Python. Cross-chart resources and
  deliberate platform exceptions can produce legitimate findings; exact
  resource/rule context is recorded, never a namespace-wide exemption.
- Helm unsupported `valuesObject`, inline values or remote charts are not silently
  interpreted. Local rendering fails closed if a supported contract changes;
  external-chart consumers remain an explicitly unimplemented validation scope.
- Policy tools are not deployment repair tools. No live dry-run/admission call,
  image pull, test hook, writer restart, RBAC update or network change is needed.

### Python, shell, Ansible and Actions

Sources: [Ruff](https://docs.astral.sh/ruff/),
[ShellCheck](https://www.shellcheck.net/),
[ansible-lint profiles](https://ansible.readthedocs.io/projects/lint/profiles/),
[Hadolint](https://github.com/hadolint/hadolint),
[zizmor](https://docs.zizmor.sh/),
[actionlint](https://github.com/rhysd/actionlint),
[GitHub secure use](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions).

Ruff combines the chosen Python bug/security/modernization rules without stacking
multiple substantially overlapping linters. Bandit was evaluated, not retained as
an unconfigured extra. Strict mypy/typing, complexity thresholds and whole-tree
formatting need a deliberate gradual typing/style policy; they are not falsely
advertised as covered by Ruff. New CI code has its own clean strict lint/format
boundary and adversarial regression tests.

Ansible `production` profile is intended for published/certified content, not a
synonym for every private homelab role being safe to run. The chosen safety profile
requires collection/prerequisite handling. Passing a directory once produced a
zero-file non-result; explicit files avoid that false confidence. A full input
scan then reproduced an ansible-lint `_AnsibleTaggedList` AttributeError around
`ansible/roles/vpn_transit/tasks/main.yml`, with both tested core versions. This
is a tool failure, not0violations. The node is clearly advisory until compatibility
is resolved; no ignored traceback or fake successful report is emitted.

Actionlint validates syntax/expressions, zizmor complements it with security
analysis. The current actionlint wrapper disables optional ShellCheck/pyflakes
subprocess integrations explicitly; the standalone shell node covers `.sh` only.
Inline workflow shell is therefore a remaining coverage gap, not a claimed pass.
A subsequent policy can enable its locked ShellCheck without baseline ambiguity.
The trusted generated publisher legitimately uses `workflow_run`; exact context
and `qg validate` protect it instead of suppressing the rule on every workflow.

### Tests, secrets and dependency feeds

Sources: [pytest JUnit](https://docs.pytest.org/en/stable/how-to/output.html),
[Gitleaks](https://github.com/gitleaks/gitleaks),
[pip-audit](https://github.com/pypa/pip-audit).

The initial expanded offline discovery ran831cases:783passed,42failed,6skipped.
This is a dated local discovery, not a green Linux/PR acceptance claim. Several
checks encode old inventory/placement/activation/version assumptions, and some
need tools/old artifacts. Do not replace expected values blindly or mark all
failures xfail to manufacture a clean graph. The PR keeps such failures visible;
they must be reviewed before promoting the full expansion to main.

Gitleaks initially flagged51contexts. Bounded structural review identified artifact
hashes, public peer keys, native resource/group/trace IDs, upstream dummy samples
and prose, not credential payloads. Exceptions record exact context hashes and
individual reasons. No token/private-key values are copied to the exception file.
A changed or new context fails again. `--record-debt` is forbidden for secret
findings: false-positive review has a separate explicit path, also forbidden in CI.

Dependency installation requires public registries/tool release downloads; normal
source/schema checks do not query production or download schemas. The dedicated
vulnerability node explicitly uses an online public advisory feed. A feed/tool
failure is a command failure, not “no vulnerabilities”. npm/runtime image audits,
SBOM/signature verification and fleet CVE coverage are not yet claimed.
