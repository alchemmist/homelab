# Scoped bot API cutover

Do not enable these switches on a bot image without API grants (migration 0026).
Keep `/telegram/webhook` and webhook secrets unchanged. Probe `/healthz` privately;
monitoring probes are not business API clients. Never publish a prefix route for `/`.

1. Provision `socrat-bot-api-admin/password` in `socrat-bot` through the secret store (32+ random bytes). Enable `publicApiEnabled` in bot production values after image rollout. Check TLS, management auth and a 401 on unauthenticated `/api/v1/cards` externally. `/v1/cards` must remain inaccessible via ingress.
2. From `/` issue separate expiring credentials. For `Socrat Alerts`: `messages:send` + `messages:advanced` (trusted card producer). The current workflow failure template also sends a structured `alert`, so it requires its own trusted `messages:send` + `messages:advanced` grant (no edit permission). A plain-text-only replacement could instead use a destination-restricted `messages:send` grant. For SPI: `cards:read`, `cards:link` and, only if its active client posts notes, `cards:note`. Do not grant message editing by default. Store SPI's token in `spi-bot-api/token` in the worker namespace. Enable `publicBotApi` on the worker only after testing access from its network policy.
3. Inventory active n8n HTTP nodes including dynamic URLs and credential references; make a private backup. Add individual Header Auth credentials (`Authorization`, `Bearer …`). Patch only URL and credential references on the current workflow versions; preserve IDs, activation and unrelated nodes. The checked-in templates contain placeholders, not live credential IDs. Do not execute production workflows to test. Compare non-mutating endpoint latency from each consumer before and after; watch naturally occurring deliveries and errors.
4. Once every consumer is accounted for and verified, set `disableLegacyApi: true` in bot production values; validate old credentials no longer work in-cluster. Retire the legacy secret only after checking non-API uses. Rotate new credentials before expiry by overlapping two grants, switching consumers, then revoking the old grant. For rollback restore legacy routes before reverting consumer credentials and URLs.

For a **new** workflow, never import the raw Git template. Create the Header Auth credential first, then render with its actual instance ID (not its bearer value): `python3 scripts/bind_bot_workflow.py TEMPLATE CREDENTIAL_ID > bound.json`. Verify the binding in the n8n editor before activating. This does not depend on n8n matching credentials by name or on their IDs looking like UUIDs. For an existing workflow use the surgical update in step 3 instead.
