# Verified placement and data ownership

- `socrat-5` hosts the Argo application-controller and Rancher. Both are single replicas, not HA. The [management handoff](https://github.com/alchemmist/homelab/blob/2fd1179442b3c7b05c9049dfa4bbaa47bfbc3790/docs/vm105-management-20261116.md) verifies native SSO, UIDs, specs, users and roles and records an intervening sign-in incident.
- PostgreSQL: seven production databases in `pg-common` and `pg-critical`. Consult CNPG for current primary placement, not an old handoff. See the [runbook, CA and retained source volumes](../../data/postgresql/postgres-platform.md).
- [Redis Insight](../../data/redis/redisinsight.md) is a shared dashboard. Sign in through `redisinsight-readers` or `homelab-owner`; membership does not grant direct Redis access.
- LiteLLM uses [shared Redis over TLS](../../data/redis/redis-common.md) for coordination, not response caching. Its primary database remains in `pg-common`. Global limits are not guaranteed if Redis is lost.
- `socrat-0` hosts Argo CD components, RustFS and vLLM/GPU. Umami and LiteLLM use `pg-common-rw`, not standalone local PostgreSQL.
- Grafana and Grafana MCP passed acceptance after their cold move to `socrat-5`. The [Grafana handoff](https://github.com/alchemmist/homelab/blob/2fd1179442b3c7b05c9049dfa4bbaa47bfbc3790/docs/vm105-grafana-20261116.md) verifies image digests, identity and ACLs, native SSO and a real MCP → Grafana → Thanos request. Grafana uses the `grafana-socrat5` claim; the old claim on `socrat-1` is stale.
- `socrat-1` hosts the SPI GitHub broker. Check the respective Applications for other components.
- `socrat-5` hosts n8n, PR Agent, WebUI, Terminal, SearXNG, the Umami application, LMS, the LiteLLM application, the renderer, Monori frontend, blog/wiki workers and SPI queue UI. Blog and Home have distributed replicas; keep anti-affinity in place.
- Stateful workloads on `socrat-5`: Wishlist, Wiki runtime, Monori backend and sync, SPI worker, format-quorum and LiteLLM branding. See the [authoritative handoff](https://github.com/alchemmist/homelab/blob/2fd1179442b3c7b05c9049dfa4bbaa47bfbc3790/docs/vm105-stateful-20261116.md). New writes on `socrat-5` are authoritative. Old claims are stale recovery sources, not current copies. Rolling back after new writes requires a fresh reverse handoff.
- GitOps no longer declares SWE Mini for Monori. [Retirement scope and verification](../../applications/ai/swe-mini.md): absence from Git does not prove removal from the cluster.
- [DeeperSeeker](../../applications/ai/deeperseeker.md) runs on `socrat-5` in namespace `deeperseeker`. LiteLLM routes `o-deepseek` here. Sign-in uses Chrome at home; the token is in the dashboard. VPN identity: `svc-free-deepseek`.
- [OpenHands Canvas](../../applications/ai/openhands.md) on `socrat-5` uses the upstream UI and Agent Server. A browser test verified shell results after closing the tab, and the native Stop-hook fixture passed. The full long-running PR loop has not passed acceptance. Owner-only oauth2-proxy/Authentik OIDC ingress is deployed. Targeted DNS was fixed; trusted TLS and SSO denial were verified from HOME and VPS. The owner's browser/MFA round trip remains unverified. No GitHub publisher is connected. PR #500 was closed externally as superseded, not marked Ready.
- Wiki: `deploy/wiki-runtime/values.yaml`, claim `wiki-runtime-socrat5`, path `/mnt/files/homelab/wiki-runtime/data`. The runtime volume is authoritative; Git sync may lag. Do not edit the managed tree concurrently with the writer.
