## Offline contract maintenance

```
uv sync --locked
uv run python ci/check_infrastructure_contracts.py
uv run python -m unittest discover -s tests -p test_infrastructure_contracts.py
```

The contract validates mesh/inventory membership/addresses, fixed relay/updater
constants against node host_vars/mesh/public-peer identity, and nine registered
issuer consumers. It does not prove live Service IP/UID or network reachability.
On a reviewed endpoint change: confirm the actual Service and network path first,
edit the canonical JSON, then run `ci/check_infrastructure_contracts.py
--write`. All consumers are validated before any write; a late scope/shape error leaves
earlier drifted files untouched. Multiple registered scalars in one file are
merged by source offsets. This is not an OS-level multi-file transaction: an I/O
failure still requires diff review. Only registered IP scalars are regenerated, retaining comments and
remaining YAML. Review Git diff and renders before publishing. There is no
runtime generator/controller dependency, no automatic production mutation and
no TLS workaround. A new consumer must be explicitly registered and tested.

Quality Graph node `infrastructure-contracts` installs SHA-pinned setup-helm
with Helm3.19.0, uses locked PyYAML, and runs the explicit offline suite. Generated
workflows come from `qg.yaml`; use `make graph-generate` and `make graph-validate`.
Local success is not a claim that remote CI has already run or branch protection
has been changed. No broad test discovery against production is introduced.

## Stable alert graph identities

`deploy/monitoring/alert-graph-panel-ids.json` is an append-only ID ledger, seeded
from accepted dashboards. `scripts/alert_graphs.py` retains existing rule/panel
IDs, allocates new odd/even pairs above the maximum and never reuses removed IDs.
`--check` is read-only; ordinary generation appends ledger entries and regenerates
owned files. Do not sort-renumber IDs or recreate the ledger from current names:
historical incident graph links would point at different alerts. Unit regressions
cover insertion before an existing sorted name, removal, duplicates and stability.
Alert conditions, labels, thresholds and notification routing are not changed by
this generator. The current refresh updates existing stale graph artifacts and
adds the already-defined Edge Chrome service rule; no alerts were silenced.

Owner deferred backup implementation on this continuation. No archives, backup schedules or restore operations are introduced by the ownership-guard package.

## Vendored baseline inventory

`deploy/contracts/vendors.json` pins complete file inventories for Rancher,
LiteLLM (including vendored subcharts) and the Wiki runtime chart. Run
`uv run python ci/check_vendor_contracts.py`: offline, read-only, no download
or `--write` mode. Added hook/template files, removals, content changes and symlinks
fail validation. No Helm dependency update/install is performed by the checker.

This is explicitly a **reviewed Git baseline**, not proof of upstream authenticity,
a signature verification or a security audit of every file. Each entry states its
basis commit and provenance limits. Existing Rancher original-package reconstruction/
empty-default render tests and LiteLLM reversible-patch upstream hash tests run
separately in CI. The Wiki local chart is not claimed to equal a tagged upstream
release. Other vendored trees have not been certified by this three-tree inventory.

For an intentional change, review added/removed/modified files and any upstream
provenance/patch changes, then update only the affected inventory and its basis.
Do not blindly rehash all trees to silence CI, treat a version string as a source
hash, or silently fetch fresh dependencies. Restore/render/native identity checks
remain separate from byte-level inventory checks.

## One placement verifier

The same `check_target_placement.py` now backs both SSH CLI and Rancher Ansible
verification. Ansible uses its temporary script transport with `--local` on the
managed host; no nested SSH, permanent helper install or new Python package.
It requires exact ready/available/total replica counts, Running + Pod Ready
(including readiness gates), observed generation, the intended node, and
Deployment UID → current-revision ReplicaSet UID → Pod controller ownership.
Old ReplicaSets, wrong controller kinds/UIDs, unavailable or extra replicas,
missing revisions and replica0 cannot produce acceptance. Both transports have
mocked offline tests; live read-only CLI checks passed for Rancher, Grafana and
Grafana MCP on socrat-5. The Ansible transport was syntax-checked, not executed
against production during this package.

## Source and current-document pointers

`deploy/contracts/source-pointers.json` registers the root Application, local
repository URL and selected current documents/value bindings. Run
`uv run python ci/check_source_pointers.py`: filesystem/YAML only, no rendering,
network, credential helpers or runtime mutation. It checks:

- root still points to the inspected Application directory;
- unique Application identities and unambiguous source/sources/ref definitions;
- local source directories and declared Helm Chart.yaml/value files exist;
- `$values` refs resolve from repository root, not the referenced source's path;
- pointers stay inside the repository, including symlink resolution;
- selected document links exist and documented claim/default-role values still
  match source files consumed by their registered Applications.

This checkpoint covers51leaf Applications and85local source/value pointers; counts
are descriptive, not a fixed limit. Current document bindings include Wiki/Grafana
claims and Argo default RBAC. Historical receipts are deliberately not checked
against today's placement. Document bindings check explicit value mentions, not
complete prose semantics. No Markdown fragment, web-route availability, remote
chart content, computed Helm override or live PV/data authority is certified.
Non-main local revisions, external relative value files and missing optional
values are explicitly rejected rather than claimed verified; extending these cases
requires a separately reviewed contract. This is not a full Helm render validator.
