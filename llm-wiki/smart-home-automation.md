# Умный дом Яндекс и автоматизации: архитектура и границы

Актуализировано **3 ноября 2026**. Текущая политика пользователя — обращаться из
n8n прямо к внешним API, если для этого достаточно штатных HTTP-нод. Не добавлять
сервис-прокси только ради перенаправления запросов и хранения токена.

## Каналы доступа

| Назначение | Транспорт | Авторизация |
| --- | --- | --- |
| Лампы, розетки, обычные сценарии | Публичный `https://api.iot.yandex.net`, scopes `iot:view`, `iot:control` | OAuth; при работе из n8n — native credentials |
| Станция Миди: текущие календарные TTS и громкость | Внутренний облачный `https://iot.quasar.yandex.ru`: обновление и запуск выделенного сценария | Native Custom Auth credential n8n: Cookie + x-csrf-token |
| Прежняя озвучка через Glagol | Локальный WebSocket и цепочка cookies → x-token → music/device token | Историческая реализация, больше не production path |

Отсутствие TTS в публичном IoT device API не означает, что облачная озвучка вообще
невозможна. Проверен внутренний API приложения «Дом с Алисой» через сценарий.
Это **не документированный публичный контракт**; изменения Яндекса могут его
сломать. Прямой запрос `tts` к внутреннему device-actions в проверке вернул
INTERNAL_ERROR; не считать его рабочим аналогом сценария.

## Напоминания без отдельного сервиса

`n8n → PUT /m/v4/user/scenarios/{id} → POST /m/user/scenarios/{id}/actions`.

- Сценарий **Calendar reminders**: громкость 5/10, затем TTS текста напоминания.
  Пользователь подтвердил звук и громкость 50% 3 ноября. Прежняя громкость не
  восстанавливается.
- Ноды `Prepare Yandex Announcement` и `Announce via Yandex Station` вызывают
  Яндекс напрямую; бизнес-логика календаря остаётся в n8n.
- `Each Reminder` обрабатывает по одному item: нельзя сначала обновить один
  сценарий всеми текстами, а потом запустить его несколько раз с последним текстом.
- Dedup отмечается только после `status=ok` на запуске. HTTP 200 с JSON error —
  ошибка, не успех. Это всё ещё best-effort, не exactly-once и не durable queue.
- Старый `yandex-voice` выведен из эксплуатации; не восстанавливать его Helm/Fleet/
  Argo deployment при следующем изменении. Его прежний код действительно работал
  через Glagol, но отдельный под не нужен для нового облачного пути. Репозиторий
  `alchemmist/yandex-voice` архивирован: DELETE отклонён GitHub из-за scope токена;
  полное удаление не выполнено. Исходники с незакоммиченными изменениями сохранены
  приватно перед выводом из эксплуатации.
- Все секреты передаются через credentials, не поля HTTP-нод и не Code-строки.
  Локальные instance mappings/восстановительные артефакты — только приватные 0600.
- Cookie/CSRF credential не обновляется автоматически. Старые cookies могли читать
  устройства, но получать 403 на действиях; свежая web-сессия это исправила.
  При истечении сессии выполнить контролируемое обновление credentials; не
  выдумывать auto-refresh и не отключать CSRF/TLS ради обхода проблемы.
- Исходник workflow, тесты и runbook: `docs/n8n/`, `scripts/n8n/sync.py`,
  `tests/n8n/`. Персональные device/scenario IDs внедряются из приватного mapping.

## Владельцы сценариев и выбор слоя

- **n8n** — пользовательские условия, календарь, уведомления, внешние webhook,
  правила про дом и расписание. Один сценарий — один владелец.
- **CronJob Kubernetes** — инфраструктурные задачи: бэкапы, метрики, housekeeping,
  сертификаты. Не дублировать пользовательское расписание отдельным cron-подом.
- **Отдельный backend** — только когда есть содержательная необходимость:
  сложная проверка диффов, файловые операции или библиотека/протокол, неудобные для
  штатных нод. Blog Updates worker остаётся: он не является пустым HTTP-прокси.
- Home Assistant сейчас не нужен; вернуться к нему можно при реальных требованиях
  к Zigbee/Matter/другим локальным интеграциям.

## Правила для агентов

- Не требовать capability-сервис по умолчанию: старое правило отменено пользователем.
- Новые API-интеграции начинать с штатных нод и native credentials.
- Не путать hardware ID Glagol и ID устройства облачного IoT API.
- Не перезаписывать другие облачные сценарии; использовать выделенный ID.
- Не создавать тестовую озвучку без предупреждения. Не удалять рабочий путь, пока
  замена не проверена. После проверки убрать старые workload, Secret и credentials.
- Workflow JSON, mapping renderer, тесты, deployment и wiki должны соответствовать
  друг другу. Не называть внутренний API публичным и не скрывать ограничения.
