# Умный дом Яндекс и автоматизации: архитектура и границы

Срез на **12 октября 2026**. Зафиксированные решения по интеграции умного дома Яндекса и организации автоматизаций в кластере. Это контракт для агентов: не плодить дублирующие сценарии и соблюдать границы слоёв.

## Доступ к умному дому Яндекса: два канала

Оба канала проверены вживую 2026-10-10..12.

| Канал | Транспорт | Для чего |
| --- | --- | --- |
| Лампы, розетки, светильники, сценарии («Чай», «Вечер» и др.) | Облачный IoT API `https://api.iot.yandex.net`, OAuth-приложение со scope `iot:view`, `iot:control` | Включение, яркость, цвет (HSV и температура), запуск сценариев |
| Яндекс Станция Миди: озвучка (TTS), громкость, медиа | Локальный WebSocket `wss://192.168.0.17:1961` (протокол «глагол», payload `update_form` → `repeat_phrase`) | Голосовые уведомления: алерты, напоминания из календаря |

### Устройства (id из `GET /v1.0/user/info`)

- Спальня: Розетки 1–3, «Лампа» `da3eb81b-f493-4556-b57b-850ad450e71e` (on_off/brightness/color hsv+temp), «Эмби лампа» (плюс световые сцены).
- Комната: «Лампа», «Светильник» `a9be424c-1abd-4bb9-98af-18dd98d72458`, Станция Миди `4416c9aa-...` (в IoT API декоративна).
- 8 сценариев: Чай, Ночь, Утро, Посвети, Вечер, Созвон, Спать, «Ася хороший котик». Запуск: `POST /v1.0/scenarios/{id}/actions`.

### Особенности, которые надо помнить

- IoT API не принимает `quasar.action`: озвучить текст через облачный API нельзя, Станция управляется только локальным протоколом.
- Цепочка авторизации Станции: cookies Яндекс-сессии → x-token (`mobileproxy.passport.yandex.net/.../token_by_sessionid`, client_id `c0ebe342af7d48fbbbfcf2d2eedb8f9e`) → music token (`oauth.mobile.yandex.net/1/token`) → `quasar.yandex.net/glagol/device_list` (host/port в `networkInfo`) и `glagol/token?device_id&platform` → WSS `wss://<ip>:<port>` с payload `{conversationToken, id, payload, sentTime}`.
- Секреты: IoT-токен — `~/.config/yandex-iot/token`; cookies — уровень пароля. В кластере оба живут в Kubernetes Secrets, не в коде и не в образах.
- У облака Яндекса нет webhook'ов: состояния устройств только опросом.
- Станция не отвечает на ICMP, но порт 1961 доступен из домашней LAN. Клиентские машины с VPN-туннелями иногда теряют маршрут до LAN — сервисы для Станции запускать на узлах кластера (socrat-0/1), не на ноутбуках.
- Home Assistant сознательно не используется: текущие сценарии решаются прямыми API. HA — опция на случай устройств с локальными протоколами (Zigbee, Matter).

## Двухслойная архитектура автоматизаций

1. **Capability-сервисы** — тонкие stateless HTTP-обёртки над физическими каналами. Код в гите, деплой Helm-чартами в `charts/`, секреты в Secrets, бизнес-логики внутри нет. Планируются:
    - `voice`: `POST /say {text}` — озвучка через Станцию.
    - `yandex-home`: управление лампами, розетками, сценариями через IoT API (цвет, яркость, вкл/выкл, запуск сценария).
2. **n8n** — единый оркестратор событийной логики: календарь → напоминание голосом, webhook алертов → TTS + красный свет, будущие правила про дом и расписание. Один сценарий = один workflow, включается тумблером. n8n знает о capability-сервисах только по HTTP и не содержит яндексовых токенов. Self-hosted в кластере (Sustainable Use license: внутреннее использование ок). Workflow версионировать экспортом JSON в гит рядом с чартом.

## Граница: CronJob Kubernetes vs n8n

- **CronJob в K8s** — инфраструктура: работа с данными и кластером без пользовательской логики (перекладка метрик, ротация бэкапов, сбор мусора, сертификаты). Существующая джоба метрик остаётся здесь и не мигрируется.
- **n8n** — события из внешнего мира и логика про «мой день и мой дом»: уведомления, календарь, алерты, умный дом, Telegram.
- Правило: **у каждого сценария ровно один владелец**; задача не выполняется одновременно через CronJob и n8n.
- При сомнении: нет пользовательского условия и внешнего события → CronJob; есть «если X, то уведоми/сделай» → n8n.

## Правила для агентов

- Не встраивать вызовы яндексовых API с токенами прямо в workflow n8n — всегда ходить через capability-сервисы.
- Новые умные сценарии добавлять в n8n, не плодить отдельные поды с cron-логикой.
- Напоминания и алерты озвучиваются только через `voice`-сервис; WebSocket Станции нигде больше не открывать.
- Изменение этой памятки сопровождать обновлением соответствующих чартов в `charts/`, чтобы wiki и код не расходились.
