title: Доступ к нодам по SSH
---

Для веб-панелей используйте публичный HTTPS и личный вход через Authentik. NetBird нужен администратору для доступа к нодам, а не для открытия Grafana, wiki, Harbor или Argo CD.

## Что запросить до подключения

1. Личную учётную запись Authentik с MFA и согласованный допуск в NetBird. Группа `netbird-internal-admins` — доверенный сетевой доступ к узлам, не обычная роль читателя.
2. Отдельного Linux-пользователя или явно согласованную SSH-привязку. Сгенерируйте собственную SSH-пару и передайте администратору **только public key**.
3. Проверенные host keys и готовые SSH aliases. Права sudo, Rancher и Kubernetes RBAC согласуются отдельно; ключ владельца и его kubeconfig не выдаются.

Не просите `homelab-owner`, Authentik superuser или NetBird owner/admin для обычной работы.

## Подключить устройство

1. Установите официальный клиент [NetBird](https://netbird.io/download).
2. Выберите self-hosted management server `https://netbird.socrat.alchemmist.xyz`, а не NetBird Cloud.
3. Нажмите Connect и войдите своей учётной записью Authentik, завершив MFA.
4. Проверьте Connected и доступность согласованных узлов. Каждое устройство получает собственную identity; не копируйте профиль другого человека.

Setup key, персональный WireGuard-конфиг, ручные static routes, split-DNS и SSH jump-host для штатного onboarding не нужны. Отдельное ручное одобрение каждого нового устройства сейчас не требуется: допуск определяется группой и личным MFA. Если вход не проходит, не обходите group admission.

NetBird выдаёт только четыре маршрута к адресам нод `/32`: это не exit node, не вся домашняя LAN, не Pod/Service CIDR. DNS устройства и обязательный рабочий VPN не перенастраиваем. Маршрут к хосту сам по себе **не является ограничением по порту или правом входа**; веб-приложения продолжают использовать штатные HTTPS-входы и роли.

## Открыть SSH

| Alias | Внутренний адрес | Порт |
| --- | --- | --- |
| `socrat-0` | `10.250.0.1` | `2222` |
| `socrat-1` | `10.250.0.3` | `2222` |
| `socrat-2` | `10.250.0.2` | `2222` |
| `socrat-3` | `10.250.0.5` | `2222` |

После установки выданного alias и собственного ключа:

```sh
ssh socrat-0
```

Alias должен использовать согласованный Linux username, личный IdentityFile и pinned host key. Не добавляйте публичный fallback/ProxyJump и не принимайте новый ключ вслепую. При изменении host key остановитесь и сверяйте fingerprint через доверенный канал; не удаляйте known_hosts и не используйте `StrictHostKeyChecking=no`.

## Диагностика и отзыв

- Timeout: статус NetBird, правильный self-hosted server, нужный `/32` route, доступность узла. Не меняйте global DNS и корпоративные маршруты.
- `Permission denied (publickey)`: Linux username, выбранный личный ключ и установленный public key. Успешный Authentik не добавляет authorized_keys.
- Нет sudo/kubectl: это отдельные права, а не неисправность NetBird. Не копируйте `/etc/rancher/k3s/k3s.yaml` как обход RBAC.
- Потерянное устройство: сообщите владельцу для отзыва device/session и SSH key. При offboarding отдельно отзываются NetBird admission, устройства, Linux/SSH/sudo, Kubernetes и роли приложений. Удаление одной группы не закрывает мгновенно старые sessions/forwards.

Независимый аварийный WireGuard-доступ остаётся у владельца, обычно выключен и не входит в обычный onboarding. Межнодовый транспорт не заменяем и его ключи не раздаём новым людям. Первый вход каждого нового администратора принимаем на его реальном устройстве: тестовая учётная запись этого не заменяет.
