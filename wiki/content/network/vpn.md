Обычные веб-сервисы Socrat открываются по **публичному HTTPS с личным входом Authentik и MFA**. Для Grafana, wiki, Harbor, Argo CD и Rancher не нужны специальный VPN или приватный DNS. Роли и исключения с отдельным native login описаны в [получении доступа]({{< relref "start/access.md" >}}).

## Не путать три разных назначения

| Назначение | Как подключаются | Чего это не даёт |
| --- | --- | --- |
| Веб-панели Socrat | HTTPS → Authentik/MFA → native роль сервиса | Автоматического admin-доступа к приложениям/кластеру |
| Работа администратора с нодами | Личный NetBird через Authentik/MFA, затем обычный SSH со своим ключом | Linux account, sudo, Kubernetes RBAC или права приложений |
| Пользовательский VPN для своего устройства | Отдельная персональная подписка/профиль | Допуска к узлам, прав администратора или аккаунта Authentik |

## NetBird — для администраторов узлов

Штатный administrative transport — NetBird с self-hosted server `https://netbird.socrat.alchemmist.xyz`. Нужны личная учётная запись, MFA и согласованная группа. Setup keys, профиль владельца и ручная настройка DNS не выдаются.

Доступ ограничен маршрутами к четырём адресам нод `/32`; это не default route/exit node и не доступ ко всем сетям. DNS устройства и корпоративный VPN оставляем как есть. Сетевой маршрут не подменяет авторизацию SSH и не предназначен для обхода Authentik у веб-панелей.

Пошаговая установка, адреса нод, SSH keys и диагностика вынесены отдельно: [Доступ к нодам по SSH]({{< relref "network/ssh.md" >}}). Независимый recovery transport обслуживается владельцем и не является обычным способом входить в приложения.

## Пользовательский VPN

Пользовательский сервис использует `vpn.alchemmist.xyz`, но открытие домена не заменяет импорт персональной подписки. Согласуйте устройство/ОС и получите подходящий клиент, ссылку или профиль через защищённый канал. Ссылка подписки содержит данные доступа: не публикуйте её, QR или весь config.

Такой VPN не даёт доступ к Kubernetes и не нужен для чтения/редактирования wiki. Не переносите настройки одного устройства на другое без согласования; при потере устройства сообщите владельцу для отзыва.

## Как сейчас устроен транзит пользовательского VPN

По состоянию на **10 ноября 2026** рабочая схема такая:

```text
Устройство → московский вход → защищённая межсерверная сеть → VPN-сервер в NL → Интернет
```

В Москве работает один контейнер **Xray-core** в Pod `vpn-transit`. Он принимает
TCP/UDP и пересылает поток на фиксированный сервер в Нидерландах. Это штатное
проксирование Xray, а не новая самописная криптография и не вторая панель 3x-ui.
Межсерверное соединение защищено существующим WireGuard; отдельный дополнительный
WireGuard для этого транзита больше не используется.

Московский relay не завершает клиентские VPN-протоколы, не проверяет учётные записи
и не выбирает страны по посещаемым сайтам. Пользователи, ключи, лимиты, подписки
и завершение VPN остаются на сервере NL под управлением существующей **3x-ui**.
TCP-соединение при этом проксируется: адрес источника для backend меняется,
сквозное сохранение реального клиентского IP не обещается.

Pod запускается в Kubernetes, но локальный watchdog работает независимо, через
systemd. При подтверждённом отказе пути он сначала исключает одновременный запуск
двух relay, затем поднимает тот же Xray с тем же конфигом вне Kubernetes. Один лишь
отказ API Kubernetes не переключает исправный relay. Обратный переход управляемый;
это не резервный VPS и не гарантия работы при отказе самого хоста или канала в NL.

### Какой IP видят сайты

- Трафик, отправленный в пользовательский VPN, выходит **из NL**.
- Существующий профиль Happ предусматривает прямой обход российских доменов и ряда
  сервисов. Панель настроена добавлять этот профиль к подпискам; его активацию на
  каждом устройстве проверяют отдельно.
- «Напрямую» в Happ означает **мимо Happ**, а не обязательно российский IP: остаётся
  влияние текущего провайдера, страны и других системных VPN.

**Решение владельца: серверное разделение РФ/зарубежье пока не внедрять.**
Исследование сохранено, но не является заданием к развёртыванию. Существующие
подписки, клиентский обход и рабочую схему Москва → NL оставляем без изменений.
Новая подписка для этого решения не нужна. Профили/QR/персональные ссылки здесь
не публикуются.

## Если что-то не открывается

Для веб-панели проверяйте адрес, HTTPS, вход Authentik/MFA и native роль; для SSH — отдельную инструкцию NetBird. Не включайте случайные туннели, не меняйте global DNS/resolvers, не очищайте системный DNS cache и не отключайте TLS verification ради обхода ошибки. Доступность public Internet/provider проверяется отдельно: Connected не означает universal connectivity.
