Некоторым автоматизациям нужен выход к зарубежным API через VPN. Для этого
каждому сервису выдаётся **собственный доступ**, отдельно от личных подписок
пользователей и административного доступа к серверам.

## Как это работает

```text
Приложение → VPN-клиент рядом с приложением → московский вход → NL → нужный API
```

Доступ создаётся в существующей панели **3x-ui**, в группе **services**.
Приложение получает свою подписку, а совместимый серверный VPN-клиент использует
её для соединения. Ставить пользовательский интерфейс Happ на сервер не требуется:
нужен клиент, поддерживающий фактический формат подписки и протокол.

Через VPN направляют только необходимые обращения. Остальные соединения
приложения и сеть сервера не должны меняться. Шифрование HTTPS до конечного API
сохраняется: отключать проверку сертификатов нельзя.

## Как запросить доступ

Передайте администратору:

- название сервиса и кто за него отвечает;
- какие API и адреса ему нужны, включая отдельный адрес авторизации;
- где он работает и сколько у него реплик;
- что должно остаться вне VPN.

Администратор создаст отдельного клиента в группе **services**, выберет подходящую
подписку и подключит VPN-клиент к приложению. По умолчанию у постоянных сервисов
**нет лимита трафика и автоматического срока окончания**. Другие ограничения
согласуются заранее, а не появляются неожиданно.

Подписка — это секрет доступа, как пароль. Её нельзя публиковать в wiki, чате,
issue или репозитории; нельзя копировать личную подписку для общего приложения.
Она хранится в защищённом хранилище сервиса.

## Что проверяют после подключения

Надписи «Connected» недостаточно. Нужно убедиться, что нужный API доступен через
VPN, посторонний трафик идёт прежним путём, а реальная автоматизация работает.
Например, для n8n уже используется отдельный service-клиент для Google API и
авторизации Google; другие обращения не перенаправлены в этот VPN.

Это не гарантия бесперебойности: приложение зависит от VPN-клиента, московского
входа и сервера в NL. Работа самого VPN не доказывает исправность OAuth или прав
доступа к конкретному API.

## Если доступ больше не нужен

Сообщите администратору: он отключит именно клиента этого сервиса и уберёт его
подписку из приложения. Личные устройства и другие сервисы трогать не нужно.
Если подписка утекла, сообщите сразу — её потребуется отозвать или заменить.

**Не путайте назначения:** межсерверный WireGuard связывает инфраструктуру,
NetBird и SSH нужны для администрирования, а service-подписка даёт приложению
выход к нужным внешним ресурсам. Новый SSH-туннель вместо service-подписки —
не штатный способ подключения.
