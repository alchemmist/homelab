title: "Как добавить секрет приложения в Rancher"

Разберём на примере Schoolbot. Цель — передать контейнеру настройки через Kubernetes Secret `schoolbot-env` в пространстве имён `schoolbot`. Разработчик может ввести значения прямо в [Rancher](https://rancher.socrat.alchemmist.xyz), не пересылая `.env` в чат. При этом администратор кластера технически может прочитать Secret: форма не заменяет менеджер секретов.

## Открыть нужное пространство имён

Войдите через Authentik, откройте кластер **Socrat** и в проводнике кластера выберите пространство имён **schoolbot**, затем **Storage → Secrets**. Не выбирайте **Project Secrets**: секрет нужен только одному приложению. Роли наблюдателя недостаточно для записи. Если кнопки создания или редактирования нет, попросите оператора подготовить `schoolbot-env` и выдать доступ к конкретному объекту, а не ко всем секретам кластера.

![Список секретов: ① выберите пространство имён schoolbot, ② откройте Storage → Secrets, ③ нажмите Create.](https://rustfs.socrat.alchemmist.xyz/public/wiki/rancher-secrets/navigation-5460d82cf9fb.png)

Список секретов: ① выберите пространство имён schoolbot, ② откройте Storage → Secrets, ③ нажмите Create. [Открыть в полном размере](https://rustfs.socrat.alchemmist.xyz/public/wiki/rancher-secrets/navigation-5460d82cf9fb.png).

- Если `schoolbot-env` **уже есть**, откройте меню **⋮ → Edit Config** и перейдите к заполнению полей. Сохраните существующие ключи.
- Если его **нет** и у вас есть право создания, нажмите **Create → Opaque**. Тип `Registry` предназначен для скачивания образов (`schoolbot-harbor-pull`), а `TLS Certificate` — для сертификата. Их менять не нужно.

![Выбор типа: ① нажмите Opaque.](https://rustfs.socrat.alchemmist.xyz/public/wiki/rancher-secrets/type-df296bd1e817.png)

Выбор типа: ① нажмите Opaque. [Открыть в полном размере](https://rustfs.socrat.alchemmist.xyz/public/wiki/rancher-secrets/type-df296bd1e817.png).

## Заполнить форму

Проверьте **Namespace**: `schoolbot`. В **Name** укажите `schoolbot-env`. На вкладке **Data** нажимайте **Add** для каждой пары: в **Key** — точное имя переменной, в **Value** — её значение. Кодировать в base64 или обрамлять значение кавычками не нужно. На снимке показана одна строка с **учебным** значением `DEMO-ONLY`: не используйте его при запуске.

![Форма: ① имя секрета, ② ключ, ③ значение, ④ создание после заполнения всех строк.](https://rustfs.socrat.alchemmist.xyz/public/wiki/rancher-secrets/data-d335010d1c14.png)

Форма: ① имя секрета, ② ключ, ③ значение, ④ создание после заполнения всех строк. [Открыть в полном размере](https://rustfs.socrat.alchemmist.xyz/public/wiki/rancher-secrets/data-d335010d1c14.png).

Текущий [Deployment Schoolbot](https://github.com/alchemmist/homelab/blob/main/charts/schoolbot/templates/deployment.yaml) читает **все шесть ключей из одного Secret**:

| Ключ | Кто и чем заполняет |
| --- | --- |
| `DATABASE_USERNAME` | Оператор: имя роли из `postgres/schoolbot-db`. |
| `DATABASE_PASSWORD` | Оператор: пароль той же роли. Чарт подставляет его в адрес подключения, поэтому специальные символы пароля должны быть закодированы для URL. Это не base64. |
| `APP_MASTER_KEY` | Разработчик: мастер-ключ в формате, который принимает приложение. При переносе используется прежний ключ. |
| `SESSION_SECRET` | Разработчик: секрет сессий по требованиям приложения. |
| `ADMIN_USERNAME` | Разработчик: имя администратора **бота**, не Rancher. |
| `ADMIN_PASSWORD` | Разработчик: пароль этого администратора. |

Если оператор уже внёс два ключа БД, добавьте только остальные четыре, **не заменяя весь объект**. Право редактирования через форму предполагает чтение этого Secret, включая поля БД. Если разработчик не должен видеть пароль БД, сначала разделите секреты и обновите ссылки в Deployment: права Kubernetes нельзя выдать на отдельные поля одного Secret. Не сохраняйте пустые или примерные значения вместо рабочих. Для восстановления держите резервную копию в согласованном защищённом хранилище.

## Сохранить и проверить запуск

Нажмите **Create** при создании или **Save** при редактировании. Откройте **Workloads → Pods** в `schoolbot`, выберите под бота и проверьте **Events**. Если Pod ожидал Secret, Kubernetes повторит запуск сам. Важен текущий статус `Ready`, а не исчезновение старых событий. Если всё ещё появляется `secret not found`, сверьте имя и пространство имён; если не найден конкретный ключ — его написание и регистр. Ошибка `ImagePullBackOff` относится к скачиванию образа, а не к переменным процесса.

Если приложение **уже работало**, значения переменных окружения не обновятся в запущенном процессе: после изменения Secret согласуйте перезапуск Deployment с оператором. Мержить значения в Git и запускать синхронизацию Argo CD вручную не требуется.
