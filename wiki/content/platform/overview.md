---
title: "Как устроена платформа"
weight: 10
---

Приложения Socrat работают в Kubernetes-кластере на базе k3s. Пользователь обращается к домену, а входной прокси направляет HTTPS-запрос в нужный сервис. Сертификатами управляет cert-manager.

| Компонент | Назначение | Кому нужен прямой доступ |
| --- | --- | --- |
| Kubernetes / k3s | Запуск и размещение приложений | Администратору |
| Rancher | Управление кластером | Администратору с отдельными правами |
| Traefik и cert-manager | Маршрутизация HTTPS и сертификаты | Обычно пользователю не нужен |
| Open WebUI | Интерфейс чата и файлов | Пользователю чата |
| LiteLLM | Авторизация API, ключи и маршрутизация к модели | Владельцу API-клиента в пределах выданных прав |
| vLLM | Выполнение модели на GPU | Прямого публичного API нет |
| Open Terminal | Выполнение инструментов чата | Через подключение Socrat Terminal |
| Prometheus и Grafana | Сбор и просмотр метрик | Разрешённым пользователям мониторинга |
| Uptime Kuma | Проверки доступности | Пользователю — статусная страница |
| Remark42 | Комментарии в блоге | Через интерфейс комментариев |
| Image proxy | Доставка изображений для приложений | Через использующее его приложение |

Обычный запрос модели проходит цепочку **Open WebUI или API-клиент → LiteLLM → внутренний шлюз → vLLM**. Терминал выполняет команды отдельно от модели. Наличие доступа к чату не даёт доступ к управлению Kubernetes.

Rancher доступен по адресу [rancher.socrat.alchemmist.xyz](https://rancher.socrat.alchemmist.xyz). Используйте его только при выданном административном доступе. Не обходите штатные интерфейсы приложений прямыми обращениями к внутренним компонентам.

Несколько узлов не означают, что каждый сервис автоматически отказоустойчив: модель зависит от одной GPU, а отдельные приложения используют локальное хранилище. Текущую доступность смотрите на [странице статуса]({{< relref "observability/status.md" >}}).
