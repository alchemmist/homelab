[Открыть n8n](https://n8n.socrat.alchemmist.xyz/).

n8n связывает сервисы в автоматические сценарии: событие запускает цепочку шагов, которая проверяет условия и выполняет действие. Например, получает событие из календаря или анализирует изменения в GitHub с помощью локальной модели.

## Доступ и запуск

n8n открывается по публичному HTTPS через Authentik MFA-gate, затем использует собственную учётную запись n8n. Это не native OIDC: нужны отдельно допуск в gateway и native права. Текущий gateway owner-only; новому администратору доступ не выдаётся автоматически. VPN/DNS overrides не нужны. Согласуйте доступ с владельцем, не используйте его пароль или session.

Откройте workflow, чтобы увидеть его этапы. В разделе **Executions** доступны результаты запусков и ошибки отдельных шагов. Активный workflow запускается по своему событию или расписанию. Ручной запуск также может отправить уведомление или изменить внешний сервис — перед тестом проверьте, что делает последний шаг.

## Примеры на Socrat

**Напоминания из Google Calendar.** Раз в минуту сценарий проверяет календарь и озвучивает напоминания через Яндекс Станцию Миди. Используются индивидуальные popup-напоминания, явно заданные у события; напоминания календаря «по умолчанию» не учитываются. Повторные опросы не должны повторять уже озвученное сообщение.

**Updates блога.** Цепочка состоит из четырёх этапов:

**Blog push → Validate via LiteLLM → Generate via LiteLLM → Create Pull Request**

После push в `main` модель Qwen через LiteLLM решает, заслуживают ли изменения новости, а затем отдельным запросом формулирует запись. Цель — предложить небольшой PR, который автор проверяет и сливает вручную, без автоматической публикации.

Сейчас этот сценарий работает в **dry-run**: анализ и генерация включены, создание PR отключено. Включённый workflow не обязательно означает, что запись во внешние сервисы разрешена.

## Как добавлять сценарии

Делите цепочку на понятные смысловые этапы и называйте блоки по-английски. Не собирайте всю логику в один блок и не дробите её на десятки мелких действий. Пояснения храните в документации, без жёлтых карточек на схеме.

Подключения настраиваются через **Credentials**. Для Google потребуется согласие в браузере, для GitHub — отдельный доступ к нужному репозиторию. Для каждого сценария с моделью используйте отдельный [ключ LiteLLM]({{< relref "ai/api.md" >}}), а не административный ключ.

Сначала проверяйте сценарий без записи в сервисы, затем включайте реальные действия. Не храните токены в блоках и не публикуйте их в экспорте workflow. Определения workflow сохраняются в репозитории homelab, чтобы изменения можно было проверить и воспроизвести.

## Если запуск завершился ошибкой

Откройте **Executions** и посмотрите, какой шаг не выполнился. Проверьте авторизацию и доступность подключённого сервиса. Перед повтором убедитесь, что предыдущий запуск не успел отправить сообщение или создать PR: повторный запуск не всегда безопасен.
