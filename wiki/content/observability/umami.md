Адрес: [umami.alchemmist.xyz](https://umami.alchemmist.xyz).

Umami показывает статистику посещений подключённых сайтов. Сейчас у нас self-hosted **3.4.1**: для панели нужна **отдельная учётная запись Umami** и права на конкретный сайт/команду. Вход через Authentik для этой панели **ещё не настроен**; это исключение из общего SSO, а не повод использовать пароль Authentik как пароль Umami.

Попросите администратора указать сайт и выдать нужную роль. Если сайт отсутствует в списке, сначала проверьте permissions, не создавайте вторую копию сайта.

## Статус OIDC

В проверенном upstream 3.4.1 нет generic OIDC-клиента, который можно подключить к Authentik одним env-параметром. Route `/sso` принимает внутренний Umami token; это не Authentik authorization-code flow. Передача общей native admin session через него не считается персональным SSO.

Возможны два отдельных проекта: Authentik MFA-gate перед UI **с сохранением native login**, либо полноценная поддерживаемая OIDC-интеграция с личными identities и native roles. Ни один из них не объявлен уже внедрённым. Внешний gate нельзя ставить на весь домен: он не должен ломать tracker script, сбор событий и согласованные публичные share pages/API.

## Как читать данные

Выберите сайт и период. Посещения — не проверка доступности: отсутствие событий бывает из-за отсутствия трафика, блокировки скрипта браузером или настроек сбора. Здоровье смотрите на [странице статуса]({{< relref "observability/status.md" >}}).

Для обращения за помощью укажите сайт, даты и ожидаемый показатель без данных других сайтов/пользователей, токенов и административных настроек.
