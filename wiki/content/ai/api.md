---
title: "API и ключи LiteLLM"
weight: 10
---

Базовый адрес OpenAI-совместимого API: `https://llm.alchemmist.xyz/v1`. Модель: `qwen3.8-27b`.

Попросите администратора выдать отдельный виртуальный ключ для своего клиента. Если у вашей учётной записи есть право управлять ключами, откройте [LiteLLM → Virtual Keys](https://llm.alchemmist.xyz/ui/), создайте ключ с понятным именем клиента и разрешённой моделью. Доступные действия зависят от прав вашей учётной записи.

Для разных приложений используйте разные ключи: тогда один можно отозвать, не отключая остальные. Не используйте административный master key как клиентский ключ. Параметры RPM/TPM ограничивают число запросов и токенов, но денежный бюджет не отражает загрузку локальной GPU: стоимость локальной модели в шлюзе задана нулевой.

Пример проверки с ключом, предварительно загруженным в переменную окружения `SOCRAT_API_KEY`:

```sh
curl --fail-with-body https://llm.alchemmist.xyz/v1/models \
  -H "Authorization: Bearer $SOCRAT_API_KEY"
```

Пример потокового ответа:

```sh
curl --no-buffer --fail-with-body https://llm.alchemmist.xyz/v1/chat/completions \
  -H "Authorization: Bearer $SOCRAT_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-27b","messages":[{"role":"user","content":"Сколько будет 2 + 2?"}],"max_tokens":32,"stream":true}'
```

Не вставляйте значение ключа прямо в команду, которую сохраняете в истории или пересылаете. `401` означает проблему авторизации; `403` может означать недостаточные права. При `429` проверьте ограничения ключа и повторите позже, без непрерывных повторных запросов.
